2. What “robot data” really means on our G1

Click a topic. Each tile is a real array entry, with the actual G1 joint name or RH56E2 hand axis.

Body feedback

rt/lowstate carries the 29 body motors. Per motor, important fields include q, dq, tau_est, temperature and diagnostics. Unitree’s low-level examples also use torso IMU data.

Installed RH56E2 bridge

Panthera’s real hands use separate left/right topics: rt/inspire_hand/ctrl/l|r, state/l|r and touch/l|r. The native six-axis order is little, ring, middle, index, thumb bend, thumb rotation.

Why fine-tune GR00T?

The base model has broad manipulation priors. It does not automatically know Panthera’s exact camera geometry, RH56E2 six-axis action semantics, controller timing, object distribution or contact geometry. Fine-tuning teaches that mapping.

What usually changes?

The common post-training path focuses on the robot projector / state-action encoders and diffusion action head. Full VLM tuning is optional and far more expensive.

Panthera lesson: normalization is part of the behavior. In our first serious fine-tune, old base statistics clipped shoulder motion. A smart model can still fail if the embodiment adapter prevents the physical range it needs.

4. SONIC: a learned whole-body motor skill, not a language model

SONIC learns a reusable 64-D motion-token language. Different encoders translate robot motion, VR teleoperation or SMPL human motion into that same latent space; a single decoder produces coordinated G1 body motion at 50 Hz.

Why combine GR00T + SONIC?

Current NVIDIA G1 workflow can let the VLA output 64-D SONIC tokens. GR00T reasons about the task, while SONIC handles balance, locomotion and coordinated motor execution. Officially, the whole-body VLA stream is 64 motion values plus hand action values.

Why does Panthera still care about ma2?

In our Isaac campaign, SONIC’s recovered MuJoCo reference route worked, but ma2_7325 became the reliable manipulation-aware body controller in the PhysX twin. So SONIC is a separate whole-body route, not the controller that produced the current Isaac manipulation results.

5. π0 (Pi-Zero): another VLA with an explicit action expert

Physical Intelligence π0 combines a pretrained PaliGemma-family visual-language model with a smaller action expert. The action expert uses flow matching to turn noise into a continuous future robot trajectory.

Flow matching in easy words: during training the action expert sees a corrupted future action sequence and learns the direction that would turn it back into the demonstrated motion. At inference it starts from noise and repeatedly follows that learned direction until a plausible action trajectory emerges.

Would π0 run on Panthera G1 directly?

No turnkey mapping. We would need an embodiment transform from our 29-joint body / 6-axis hands / camera streams into π0’s configured robot vector and action space.

Why compare against it?

It is one of the clearest reference architectures for “VLM + robot action expert + flow matching”, so it helps us understand what is general across modern VLAs and what is specific to GR00T.

6. Unitree UnifoLM: VLA-0 vs WLA-1.0

Panthera evaluated

UnifoLM-VLA-0

Unitree’s earlier VLA route. Public code uses a Qwen2.5-VL-family backbone and a flow-matching / DiT action head. Panthera loaded the checkpoint and ran closed-loop inference, but did not obtain useful finger grasp/lift progress in the bounded evaluation.

Newest family

UnifoLM-WLA-1.0

Unitree’s newer 6B whole-body foundation-model family, trained on about 2,500 hours of real-robot data. Unitree documents a unified 60-D current robot representation and 54-D future action representation, with masks to handle different embodiments.

11. Panthera: which model should do what?

Keep

ma2 body policy

The E2 migration showed direct body-policy transfer. Do not retrain body locomotion just because hand geometry changed.

Calibrate

RH56E2 installed hand

Real endpoints, mount transform, coupling, timing, force/tactile and compliance are now higher-value than another large simulation fine-tune.

Short adaptation

GR00T

Preserve the best checkpoint. After hand calibration, rerun frozen, then adapt only the remaining embodiment/task gap.

Redesign grip

Whiteboard / old thumb-pad grips

The donor contact point is geometrically unreachable on E2. This is a grasp-topology problem, not a language-model problem.

Why GR00T needs adaptation but ma2 does not: ma2 mostly cares about body balance and load. GR00T must predict precise visual-to-contact behavior. Changing thumb geometry, camera-to-hand transform and contact surfaces changes the action distribution that GR00T must produce.
